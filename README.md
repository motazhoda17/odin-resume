# Motaz Hoda – Resume

My developer resume, written for the **Resumes** lesson in The Odin Project's [Getting Hired](https://www.theodinproject.com/lessons/node-path-getting-hired-building-your-resume) course.

- `resume.md` – the content in plain Markdown (easy to edit and to paste into job sites)
- `resume.html` – the designed version that prints to **exactly one US Letter page**

## How it follows Odin's advice

- **One page.** The print CSS is tuned so everything fits on a single page.
- **Projects first.** For someone changing careers, projects are the strongest proof of skill, so they come right after a short summary. Each one names the tech stack and says what I actually built.
- **Concise bullets** that start with an action verb and show a result where possible.
- **Work history still matters**: it shows other employers have trusted me. It's listed after skills.
- **No photo**, no age, no unnecessary personal details.
- Links to GitHub, the portfolio and live demos so a hiring manager can see the work in seconds.

## Files

- `Motaz-Hoda-Resume.pdf` – ready-to-send PDF (one US Letter page)
- `resume.html` – the designed version the PDF is printed from
- `resume.md` – the same content in plain Markdown, easy to paste into job sites

## Update the PDF after editing

1. Edit `resume.html` (and keep `resume.md` in sync).
2. Open `resume.html` in Chrome and press `Cmd + P`.
3. Destination **Save as PDF**, Paper size **Letter**, Margins **None**, tick **Background graphics**.
4. Check the preview says **1 page**, then save over `Motaz-Hoda-Resume.pdf`.

## What I practiced

- Writing a focused resume for a career change into software
- Turning project work into short, specific bullet points
- Print-specific CSS (`@page`, `@media print`) to control a printed page
