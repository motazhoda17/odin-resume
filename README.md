# Motaz Hoda – Resume

My developer resume, written for the **Resumes** lesson in The Odin Project's [Getting Hired](https://www.theodinproject.com/paths/full-stack-javascript/courses/getting-hired) course.

- `resume.md` – the content in plain Markdown (easy to edit and to paste into job sites)
- `resume.html` – the designed version that prints to **exactly one US Letter page**

## How it follows Odin's advice

- **One page.** The print CSS is tuned so everything fits on a single page.
- **Projects first.** For someone changing careers, projects are the strongest proof of skill, so they come right after a short summary. Each one names the tech stack and says what I actually built.
- **Concise bullets** that start with an action verb and show a result where possible.
- **Work history still matters**: it shows other employers have trusted me. It's listed after skills.
- **No photo**, no age, no unnecessary personal details.
- Links to GitHub, the portfolio and live demos so a hiring manager can see the work in seconds.

## Make the PDF

1. Fill in every placeholder (see below) in **both** files.
2. Open `resume.html` in Chrome.
3. Press `Ctrl + P` (`Cmd + P` on Mac) → Destination **Save as PDF**, Paper size **Letter**, Margins **None** (the page has its own margins), and tick **Background graphics**.
4. Check the preview says **1 page**. If your real bullets are longer and it spills onto page 2, shorten a bullet or remove the "More projects" line.
5. Save as `Motaz-Hoda-Resume.pdf` and link it from the portfolio's **Resume** button.

Tips for the experience bullets: start with a verb ("Installed…", "Trained…", "Resolved…"), add a number when you can ("…for 40+ customers a week"), and favour things that show reliability, problem-solving and communication.
